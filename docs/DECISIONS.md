# 제품 결정 기록

## 확정

| 항목 | 결정 |
|---|---|
| 리그 연결 | KBO 실제 경기 일정, 팀, 선수와 연결 |
| 기록 기준일 | 경기 전날까지 확정된 KBO 기록 사용 |
| 공식 경기 수 | 실제 KBO 경기 한 건당 팬볼 공식 경기 하나 |
| 선발투수 | 팬 투표에서 제외하고 당일 KBO 발표 선발 사용 |

| 팬볼 기록 | 저장·조회하되 KBO 기록과 분리하고 선수 능력 산정에 사용하지 않음 |
| 재현성 | 공식 시드, 선수 능력 스냅샷, 데이터 기준일과 플레이 결과 저장 |

## 현재 MVP 임시 규칙

- 투표는 브라우저 단위 데모이며 실계정별 투표 검증은 아직 없다.
- 중요 상황 작전 투표는 15초 후 최다 선택지를 적용한다.
- 작전은 매 타석이나 투구/볼카운트마다 묻지 않고, 득점권 주자, 1루 주자 무사·1아웃, 7회 이후 2점 이내 접전에서만 다음 타석 직전에 묻는다. 샘플 MVP 임시 기준.
- 컨택·강공 선택지에 다음 타자 기준 기본 분포 대비 결과 확률 변화(%p)를 표시한다. 유리한 결과 증가 초록색, 불리한 결과 증가/유리한 결과 감소 빨간색.
- 상황 문구는 `무사 1,2루`, `2아웃 만루` 형식으로 표시한다.
- 타석별 결과 분포는 100,000회 표본으로 만들고, 실제 결과는 그 빈도에 비례해 추첨한다. 최빈 결과를 고정 적용하지 않는다.
- 타석 투구 연출은 2초 간격이며, 타석 결과와 연결된 단순화된 투구 시퀀스를 표시한다.
- 현재 일정·팀·선수·상대 선발 스플릿은 샘플이다.
- 경기와 투표는 현재 브라우저 `localStorage`에 저장한다.
- 동점은 12회까지 진행한 뒤 무승부로 끝내는 임시 규칙을 둔다.

## 향후 팬 기여 랭킹 방향

- 팬볼 팀 승패 순위보다 로그인 사용자별 라인업·작전 기여 점수를 우선 검토한다.
- 점수는 성공했을 때만 플러스 적립한다. 실패·저조한 비교 결과로 기존 점수를 차감하지 않는다.
- 라인업 기여는 같은 경기의 선수별 실제 KBO 결과와 팬볼 결과를 비교하는 안을 검토한다. 예를 들어 실제 4타수 1안타, 팬볼 4타수 2안타면 양의 차이에만 점수를 줄 수 있다.
- 실제 적용된 작전뿐 아니라, 선택되지 않은 다른 작전도 같은 타석에서 비공식으로 시뮬레이션해 생산적인 결과가 나온 경우 해당 작전을 선택한 사용자에게 추가 점수를 주는 방안을 검토한다.
- 비공식 대안 결과는 공식 경기 점수·기록·진행 상태를 바꾸지 않는다.
- 세부 점수값, 기회 수 보정, 대표 라인업에 채택되지 않은 개인 라인업의 점수 귀속은 미결정이다. 로그인/서버 투표 기능과 함께 별도 설계한다. 자세한 안은 `docs/FAN_RANKING_DESIGN.md` 참조.

## 아직 비교가 필요한 설계

- 전체 라인업 후보 투표, 타순별 투표, 후보 결선 중 공정하고 참여가 쉬운 방식
- 팀·타자·투수 전력을 기록 데이터에서 추정하는 방법
- 표본이 작은 신인과 시즌 초반 기록 보정
- 실제 선발 변경 및 경기 직전 엔트리 변경 처리
- 시뮬레이션 도중 작전 투표가 경기에 미치는 영향 수준

## 데이터 사용

공식 API·서면 허가 또는 계약 공급원을 확인하기 전에는 KBO 화면을 자동 대량 수집하는 방식으로 구현하지 않는다. 공개 열람 가능성과 재배포·상업 이용 권리는 별개로 확인한다.

## 개발 관리자 모드와 실제 경기 모드

- 개발자는 `?admin=1`에서 운영 시간을 기다리지 않고 샘플 경기를 즉시 시작하고 현재 경기 또는 전체 샘플 상태를 초기화한다.
- 일반 화면에는 초기화 도구를 표시하지 않는다. 현재 배포는 소유자 전용이며, URL 모드 표시는 인증/권한 검사가 아니다. 외부 공개 전에는 서버 인증과 관리자 권한 검사가 필요하다.
- 실제 경기 모드는 경기 일정의 `scheduledStartAt`(KST)을 기준으로 시작 시각을 확인한다. 18:00~18:20 시간창에 공식 데이터가 준비되면 자동 실행한다. 정적 MVP는 탭이 열려 있어야 타이머가 작동하며, 현재 실제 KBO 데이터와 대표 라인업 연결이 없어 실행 준비 상태는 꺼져 있다.
- 운영 서비스의 단일 실행을 보장하려면 브라우저 타이머가 아닌 서버 스케줄러와 DB 중복 실행 잠금이 필요하다.
- 대표 라인업 투표는 최초 MVP 범위에서 허용된 임시안이다. 선정 방식은 확정 결정이 아니며 후보별·타순별 방식 검토가 남아 있다.

## 2026-11-12 추가 결정

- 경기 중 투구판은 타순·타격 손, 현재 타자의 오늘 타수·안타, 다음 타자 이름·타격 손을 보여 준다. 경기 종료 뒤에는 마지막 타석 결과와 승패·최종 점수를 먼저 7초간 보여 주고 결과 기록 화면으로 전환한다. 끝내기 득점도 종료 안내에 표시한다.
- 경기 결과의 타자 기록표는 타수(AB), 안타(H), 홈런(HR), 득점(R), 타점(RBI), 볼넷(BB), 삼진(K), 타율(AVG)을 표시한다. 2루타·3루타 열은 두지 않는다.
- AI 대결은 투구 속도를 빠르게 설정해도 타석 결과를 3초간 보여 준다. 빠른 투구 속도 때문에 결과 문구가 너무 빨리 사라져 다음 타석으로 넘어가는 일을 막는다.
- 경기 중 타자 옆 오늘 기록은 안타/타수 순서로 간단히 표시한다(예: 1/2, 첫 타석 전 0/0).
- 확률 분포에서 실제로 뽑힌 결과는 초록색으로 표시한다. 인플레이 결과 중 번트는 투구 payload의 `bip`가 아니라 타석 결과(`SAC`, `BUNT_HIT`, `BUNT_OUT`, `FC`)를 번트 분포 키(`sacrifice`, `hit`, `out`, `fieldersChoice`)로 대응해 표시한다.
- 야수선택(FC)은 선행 주자를 아웃 처리한다. 뒤 주자는 기존 베이스 점유 때문에 강제될 때만 진루하며, 3루 주자가 선행 주자로 아웃되면 3루를 비운다. 타자만 1루에서 아웃된 일반 땅볼은 강제 진루가 풀려 주자가 멈출 수 있으므로 무사 1,2루에서 1사 1,2루가 되는 결과도 가능하다.
- 경기 화면은 완료된 타석 결과를 별도 대기열에 보관해, 서버 지연이나 여러 갱신의 병합으로 다음 투구가 먼저 도착해도 각 결과를 최소 3초씩 차례로 보여 준다. AI 대전과 서버 경기는 같은 투구판을 사용한다.
- 타석별 로그에는 타석 전 상황을 반복해서 표시하지 않고, 결과와 함께 타석 후 주자·아웃 상황만 보여 준다.
- 투수 교체는 적용할 타석을 고정한다. AI 대전은 수비 중 다음 타석 교체와 공격 중 다음 수비 이닝 교체 예약을 제공하며, 예약된 반이닝의 첫 타석이 시작되면 적용 시점을 놓친 요청은 만료한다.
- 실시간 경기에서 수비 중 현재 투수 교체 요청은 기존처럼 해당 팀 참여자의 80%가 모이면 구원투수를 투표한다. 공격 중에는 같은 80% 기준으로 다음 수비 이닝 투수를 예약하고, 해당 반이닝 첫 타석 전에 구원투수 투표를 연다. 예약 요청은 정확한 이닝·초/말에만 적용하며 시점을 놓치면 만료한다. 별도의 수동 경기 정지 버튼은 두지 않는다.

- (2026-11-12) 선발 로테이션: 팀마다 사용자가 정한 5명(`dist/rotations.js`, `tools/build-rotations.py`). AI 대결은 우리·상대 선발을, 관리자 경기 예약은 양 팀 선발을 고른다. 선발로 나간 투수는 그 경기 불펜에서 빠진다. 투수 기록은 2026만 쓴다(2025 대체 없음). 2026 기록이 없는 투수는 리그 평균 값으로 두고 사용자에게 기록을 받는다. 사용자가 보낸 기록·구종은 `data/pitchers-manual-2026.json`.


## 2026-11-12 친구와 1대1 방

- 사용자가 방을 만들고 8자리 숫자 코드로 친구를 초대한다(비밀번호 없음, 사용자 결정 "코드만").

- 코드 입력은 계정당 1분 10회까지, 방은 24시간 뒤 만료(시작 전), 둘 다 준비하면 시작. 남의 방은 일정·생중계 목록에서 숨긴다.

## 2026-11-13 친구 방 개편

## 2026-11-14

- 작전 랭킹은 누적 합계가 아니라 투표당 평균 점수순으로 정렬한다. 비교는 관리자 경기 투표 20회부터 시작하며, 판단 효율은 해당 투표 선택지 중 최선 선택의 판단 점수 합을 100으로 환산한 비율로 별도 표시한다. 유효한 판단 기회가 없으면 효율은 표시하지 않는다. 친구 방·AI 대결의 경기 점수에도 평균과 판단 효율을 함께 표시한다.
- 친구 방 라인업 편집에도 AI 추천 채우기를 제공한다. 선택한 팀의 기존 OPS 중심 추천으로 타순과 수비를 정하고, 추천 뒤 직접 수정할 수 있다. 상대 선발이 시작 전까지 비공개이므로 투수 맞춤 추천은 하지 않는다.
