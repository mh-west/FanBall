# 타자 작전과 투수·수비 작전의 결합 모델

작성일: 2026-11-05  
상태: 설계 제안. 아래에는 KBO 실측으로 확인되지 않은 작전 보정 숫자를 추가하지 않는다.

## 목표

타격팀 팬은 타석에서 실행할 작전을, 수비팀 팬은 투수와 수비의 대응 작전을 선택한다. 두 선택이 함께 다음 경기 결과 분포를 바꾼다. 작전은 한쪽에 일방적인 이득을 주는 버튼이 아니라 상황에 맞는 장단점을 가진 선택이어야 한다.

선수 기본 능력치는 경기 전날까지 확정된 실제 KBO 기록으로 만든다. 팬볼 기록은 기본 능력치에 섞지 않는다. 공식 경기는 고정된 입력·계수 버전·시드로 한 번 실행하며, 이 문서의 반복 계산은 개발 검증과 사전 분석에만 사용한다.

## 확률 결합 방식

기본 결과 분포를 `P0(y | 타자, 투수, 좌우, 카운트, 주자/아웃, 경기 전 데이터 스냅샷)`라 둔다. 결과 `y`는 단순한 안타/아웃뿐 아니라 번트 성공, 선행주자 아웃, 주자 추가 진루, 병살, 홈 승부 등 경기 상태 변화를 구별한다.

공격 작전 `a`, 수비 작전 `d`가 선택되었을 때는 다음 구조로 보정한다.

`P(y | 상태, a, d) = softmax(log(P0(y)) + β공격(y, 상태, a) + β수비(y, 상태, d) + γ(y, 상태, a, d))`

- `β공격`: 타격팀 선택의 영향.
- `β수비`: 투수·수비팀 선택의 영향.
- `γ`: 두 작전의 상호작용. 예를 들어 희생번트 시도와 코너 내야 전진 수비의 조합.
- `softmax` 정규화를 통해 모든 결과 확률의 합은 항상 1이 된다.
- 상호작용 표본이 부족하면 `γ=0` 쪽으로 수축한다. 근거 없는 상성 숫자를 임의로 만들지 않는다.
- 카드에는 최종 결합 분포와 기본 분포의 차이를 %p로 보여준다. 유리한 효과는 초록색을 먼저, 불리한 효과는 빨간색으로 이어서 표시한다.

개발 초기에는 데이터로 추정한 계수표를 버전 관리한다. 임시 계수를 쓰는 경우 반드시 `데모 가정`이라고 표시하고 공식 경기에 적용하지 않는다.

## 예시 상황: 무사 1,2루

| 타격팀 선택 | 수비팀 선택 | 모델링해야 할 결과와 비용 |
|---|---|---|
| 강공/기본 타격 | 기본 수비 | 안타·장타·볼넷·삼진·땅볼 병살과 주자 진루를 함께 계산 |
| 희생번트 | 기본 수비 | 번트 성공, 번트 안타, 파울/실패, 타자 아웃, 선행주자 아웃 등을 분리 |
| 희생번트 | 코너 내야 전진 | 번트 타구 처리 및 내야 타구에서 홈/3루 주자를 잡을 가능성을 반영. 대신 전진 수비 뒤 땅볼·안타 처리 위험도 모델링 |
| 희생번트 | 정상 수비 또는 병살 대비 | 전진 수비와 다른 번트 처리 결과 및 병살·진루 분포를 비교 |

‘코너 내야 전진’은 그 자체로 번트를 자동 아웃시키는 규칙이 아니다. 타자 타구 방향, 번트 품질, 수비 위치, 주자 속도에 따른 결과 유형이 있어야 효과를 계산할 수 있다.

## MVP에서 제안하는 조작 방식

1. 작전 투표가 열리는 상황을 서버가 판정한다.
2. 공격팀 팬은 타격 선택을, 수비팀 팬은 수비 위치/투수 선택을 같은 제한 시간 동안 제출한다.
3. 양쪽 선택을 동시에 공개하고 결합 분포를 계산한다. 상대 선택을 보고 뒤늦게 카운터하는 이점을 방지한다.
4. 각 팀은 계정당 한 표를 행사하고, 마감 시 다수 선택을 대표 작전으로 확정한다. 동률 또는 미투표 시 기본 작전을 적용한다. 실제 계정·투표 서버가 생기기 전까지 데모 규칙으로 둔다.
5. 선택 결과·투표 수·분포·모델 버전을 경기 로그에 보존한다.

동시 투표는 MVP 제안이다. 실제 야구 감독처럼 한쪽이 먼저 배치하고 상대가 확인 후 대응하는 운영도 가능하지만, 팬 투표에서 응답 시간과 정보 접근 차이가 공정성에 영향을 줄 수 있어 별도 결정이 필요하다.

## 현재 MVP 데모 구현 상태

2026-11-05 현재 코드는 사용자별 응원팀에 맞춰 작전 카드를 역할별로 표시한다. 공격 중인 내 팀이면 기본 타격/컨택/희생번트(가능한 상황)/강공이 보이고, 수비 중인 내 팀이면 기본 수비/병살 대비/가능한 상황의 코너 내야 전진 수비가 보인다. 내 응원팀이 매치업에 없으면 선택 카드는 나오지 않는다. 공격·수비 선택 결과도 타석 로그에 따로 표시한다.

샘플 엔진에서 적용 중인 방어 수치는 아래와 같으며 모두 임의의 테스트값이다.

- 병살 대비: 1루 주자·2아웃 미만일 때 잔여 일반 아웃 중 GDP 비율을 10%에서 18%로 설정하고 단타 확률 +1.5%p.
- 코너 전진: 무사 1루·2루 이상 상황에서 번트 성공률을 72%에서 58%로 설정하고 단타 +1.5%p.
- 결과 분포는 해당 값을 반영하지만 공식 KBO 작전 성공률이나 서비스 보정값으로 사용하면 안 된다.

MVP는 브라우저 localStorage라 현재 페이지를 연 한 사용자의 My Team 역할 선택만 기록한다. 다른 구단 팬의 동시 투표, 계정별 투표 집계 및 양쪽 선택을 기다렸다 공식 타석에 반영하는 서버 흐름은 미구현이다. 관리자는 샘플 원정/홈 매치업을 바꾸어 각 구단의 공격·수비 화면을 확인할 수 있다.

## 서버 동시 투표 구현 설계

사용자 요구에 따라 공격·수비 투표를 같은 시각에 열고 같은 서버 기준 15초 마감 시각을 사용한다. 공격팀 팬은 공격 선택지, 수비팀 팬은 수비 선택지를 보며, 다른 팀 팬은 `작전 선택 중입니다`를 본다. 한쪽이 먼저 투표를 끝내도 창은 닫지 않는다. 서버가 마감 후 역할별 다수 작전을 확정하고, 동률/무표는 기본 작전을 사용한다. 구체 DB/RLS/RPC, 동시성, 재시도 처리와 UI 상태 전이는 [`SERVER_VOTING_DESIGN.md`](SERVER_VOTING_DESIGN.md)에 정리했다. 실제 다중 사용자 투표를 구현하기 전까지 localStorage 데모에는 서버 동기화가 없다.

## 작전 후보와 노출 조건

| 상황 | 공격 선택 후보 | 수비 선택 후보 | 먼저 필요한 엔진 결과 |
|---|---|---|---|
| 무사 1,2루 | 기본/강공, 희생번트 | 기본, 코너 내야 전진, 병살 대비 | 번트 성공/실패, 타구 방향, 주자별 진루와 선행주자 아웃 |
| 1루 주자, 0~1아웃 | 기본/강공, 제한적 히트앤런 | 기본, 병살 대비 수비 | 주자 스타트, 헛스윙, 병살, 도루 성공/실패 |
| 3루 주자, 0~1아웃 | 컨택/외야 희생타 등 향후 후보 | 전진 수비, 정상 수비 | 땅볼/플라이 위치, 홈 송구와 세이프/아웃 |
| 득점권, 2아웃 | 컨택/강공 | 기본 수비 및 타자 특성에 맞는 위치 | 타석 결과별 장타·주자 득점 반영 |
| 후반 접전 | 기대득점과 승리확률을 고려한 공격 선택 | 고의4구 등 데이터 지원 가능한 대응 | 이닝·점수 기반 승리확률, 다음 타자 결과, 베이스 점유 |

무리하게 모든 상황에서 양쪽에 여러 선택지를 제공하지 않는다. 해당 상황에서 실제 플레이가 가능한지, 엔진이 그 결과를 기록할 수 있는지 확인한 뒤 후보를 연다.

## 보정과 검증 절차

1. 합법적으로 사용할 수 있는 날짜별 KBO 플레이별 데이터와 가능한 경우 수비 위치·번트/작전 상황 자료를 확보한다.
2. 투구·타석 이벤트를 타구 유형, 주자 이동, 아웃, 득점, 투수/타자/수비 상태로 정규화한다.
3. 기본 분포 `P0`를 먼저 검증한다. 타자·투수 좌우, 결과 종류, 카운트, 주자/아웃, 구장, 시즌을 고려한다.
4. 작전 선택은 보통 특정 상황에서만 쓰이므로 단순 성공률 비교를 피한다. 비슷한 상황끼리 층화/매칭하고 타자·투수 능력 차이를 통제한다. 가능한 데이터에는 선택 편향과 미관측 요인이 남는다는 한계를 적는다.
5. 희귀한 조합은 상위 그룹과 리그 평균으로 계층적 수축을 하고 표본 수·구간을 함께 표시한다. 상호작용 계수는 독립 근거가 약하면 0에 가깝게 둔다.
6. 과거 경기 날짜를 순서대로 나눈 롤링 백테스트를 한다. 미래 자료가 과거 예측 입력에 섞이지 않게 한다.
7. 분포 보정도, log loss/Brier score, 기대득점(RE24), 후반 접전 승리확률(WP), 주자·아웃 기록 일관성을 확인한다.
8. 지표가 기준 모델보다 나아지지 않거나 효과 불확실성이 크면 추가 보정은 미적용 상태로 둔다.
9. 공식 경기 스냅샷에 기준일, 입력 데이터 해시, 모델/계수 버전, 선택 작전, 난수 시드를 저장한다.

## 선행 근거와 한계

현재 전략 문서의 참고 자료는 주로 MLB/NPB 연구이며 KBO 계수를 직접 제공하지 않는다. 기대득점과 승리확률로 작전을 비교하고, 희생번트·히트앤런의 이득과 위험을 함께 모델링하는 데만 활용한다. 구체적 링크 및 적용 범위는 [`STRATEGY_DESIGN.md`](STRATEGY_DESIGN.md)의 근거 목록을 참조한다.

## 공개 전 원칙

- 모델 결과를 “이 작전이 무조건 더 좋다”라고 단정하지 않는다. 예상 차이와 불확실성을 함께 제공한다.
- 특정 작전 표본이 부족하면 숫자를 꾸며 넣지 않고 `자료 부족` 또는 기본 효과 0으로 표시한다.
- 타격 작전과 수비 작전 각각의 변화뿐 아니라 결합 결과를 보여준다.
- 팬에게 라인업 이유를 글로 작성하도록 요구하지 않는다. 분석 결과를 자동 계산하고, 선택 이유 설문이 필요하면 선택형·선택사항으로만 둔다.
