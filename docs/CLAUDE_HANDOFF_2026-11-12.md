# Claude 인계 메모 · 2026-11-12

이 문서는 사용자가 Claude와 Codex를 번갈아 쓰며 진행한 FanBall 작업을 이어가기 위한 최신 요약이다. 먼저 `AGENTS.md`, 최근 `git log --oneline -20`, `docs/DECISIONS.md`를 읽는다. `PROJECT_HANDOFF.md`는 초기 기록이므로 최신 결정과 다르면 `AGENTS.md` 및 `docs/DECISIONS.md`를 따른다.

## 사용자와 작업할 때 지킬 것

- 사용자에게 보내는 답과 진행 상황은 한국어로 쓴다.
- 끝낸 작업, 확인한 것, 아직 안 된 것을 구분해서 보고한다.
- 완료한 작업은 Git 커밋과 `docs/DECISIONS.md`에 남긴다.
- Push·배포·원격 DB 적용은 별도 요청이 있을 때만 한다. 이번 2026-11-12 변경은 사용자가 명시적으로 “푸쉬, 배포”를 요청한 범위다. 이 승인으로 이후 별도 작업을 배포하지 않는다.
- 배포할 때마다 375×812 휴대폰과 768×1024 태블릿 화면을 확인한다. 가로 스크롤, 글자·버튼 표시, 콘솔 오류를 살핀다.
- 선수 기록 수집은 `AGENTS.md`의 출처·robots 규칙을 따른다.

## 이번 작업에서 사용자가 요청한 변경

1. 타석 로그에서 “타석 전” 주자·아웃 정보는 빼고, 타석 결과와 “타석 후” 주자·아웃 정보만 표시한다.
2. 선발을 특정 이닝까지 쓰고 다음 수비 이닝부터 중계 투수를 쓰도록 미리 예약할 수 있게 한다. 진행 중인 여러 팬 투표 경기에서도 경기 정지 버튼 없이 예약을 요청하고, 기존처럼 해당 팀 참여자의 80%가 모이면 구원투수 투표를 연다.
3. 예약은 지정한 회·초/말에만 유효하다. 지정 반이닝 첫 타석이 시작된 뒤에는 만료해 늦은 선택이 다음 타자나 다음 이닝에 잘못 적용되지 않게 한다.
4. AI 대전에서도 공격 중에 다음 수비 이닝 투수를 미리 고를 수 있게 한다. 시점이 지난 예약은 적용하지 않는다.
5. 완료한 결과는 커밋 기록과 `docs/DECISIONS.md`에 남기고, 이번 변경을 push·배포한다.

## 앞서 진행한 사용자 요청의 배경

- 경기 화면 타자 옆 오늘 기록은 `안타/타수` 형식(예: `1/2`)으로 간단히 보여 준다.
- 결과 분포에서는 실제로 나온 결과를 초록색으로 표시한다. 번트 결과도 타석 결과와 분포 키를 맞춘다.
- 땅볼·야수선택·병살 상황은 주자 강제 진루와 아웃 처리에 따라 결과가 달라진다. 관련 현행 판단은 `docs/DECISIONS.md`의 2026-11-12 항목을 기준으로 한다.
- 다음 투구가 먼저 도착해도 끝난 타석 결과를 건너뛰지 않도록 결과 큐에서 타석 결과를 순서대로 보여 주며, 각 결과를 최소 3초 유지한다. AI 대전과 서버 경기는 같은 투구판을 쓴다.
- 경기 종료 뒤 타자 기록에서 타수와 안타를 확인할 수 있어야 한다.
- 투수 교체의 타이밍 문제는 여러 참여자가 투표할 때 수동 경기 정지를 두지 않고, 적용할 타석·이닝을 지정하는 방식으로 해결한다.

## 이번 변경의 구현 지점

- `dist/enhancements.js`: 타석 로그는 최종 주자·아웃 상황만 표시.
- `dist/ai-game.js`: 공격 중 “다음 수비 이닝 투수 예약”과 지정 시점 만료 처리.
- `dist/engine/pitch-engine.js` 및 `supabase/functions/_shared/pitch-engine.js`: 지정 PA/반이닝에 맞춰 교체를 적용하고 시점을 놓친 예약은 폐기한다. 두 파일은 완전히 같아야 한다.
- `dist/server-game.js`, `dist/server-voting.js`: 실시간 경기에서 공격 팀이 다음 수비 이닝 교체를 요청하고 80% 집계 현황을 확인한다.
- `supabase/functions/_shared/orchestrator.js`: 실시간 요청을 목표 반이닝의 첫 타석 전에만 처리하고, 구원 투표 결과는 그 첫 타석 직전에 반영한다.
- `supabase/migrations/202611120003_next_half_pitching_change.sql`: 요청 대상 이닝/초·말 저장, 사용자 팀 검증, 지난 목표의 요청 만료.
- `dist/guide.js`, `dist/patch-notes.js`: 사용자 설명과 배포 기록.

## 배포 확인 상태

이 항목은 Codex가 이번 변경의 배포를 마친 뒤 실제 상태로 갱신한다. 이어받는 Claude는 `git status --short`, 최근 커밋, 원격 배포 상태를 확인하고 미완료 표시가 있으면 해당 단계부터 이어간다.

- 커밋 / push: 작업 완료 후 기록
- 원격 DB 마이그레이션: 작업 완료 후 기록
- `orchestrator-tick` 함수 배포: 작업 완료 후 기록
- Cloudflare 정적 사이트: `main` push 이후 자동 배포 상태와 375×812 / 768×1024 확인 결과를 기록
