# FanBall 작전 선택 설계·근거 기록

최종 갱신: 2026-11-05  
범위: 팬 작전 투표의 상황표, 트레이드오프, 출처, 현재 샘플 엔진 수치와 향후 KBO 보정 기준을 기록한다.

## 상태 구분

- **현재 MVP 구현**은 작동을 확인하기 위한 샘플 모델이다. 표에 적힌 수치가 KBO 실측 확률이나 정식 야구 통계라고 해석하면 안 된다.
- **제안**은 작전 선택지를 어디서 띄울지와 향후 실제 확률을 어떻게 추정할지에 대한 설계안이다. 히트앤런, 도루, 희생플라이 등은 필요한 경기 결과 유형을 엔진에 추가하기 전까지 확정 확률로 노출하지 않는다.
- 실제 KBO play-by-play 자료 사용 권한과 데이터 공급 계약이 확인되기 전에는 실제 KBO 확률을 주장하지 않는다.

## 제품 원칙

1. 팬 투표는 승부 예측이 아니라 다음 타석의 실행 방식을 선택한다.
2. 선택지가 기본 타격보다 모든 면에서 우월하지 않도록 이득과 비용을 함께 표시한다.
3. 선택은 다음 타석에 한 번 적용한다. 사용자가 결과를 보고 같은 타석을 다시 실행할 수 없다.
4. 후보는 주자 8가지 배치와 아웃 0·1·2개, 즉 24개 base/out state를 바탕으로 만들고, 점수 차·이닝·타자와 주자 능력으로 추가 필터링한다.
5. 확률 변경은 기본 타석 분포를 변형한 뒤 전체 합이 1이 되게 정규화한다. 투수·타자 좌우, 전날까지의 실제 KBO 기록과 표본 보정이 기본 분포에 먼저 들어간다.
6. 전략의 평가는 작전 전·후 기대득점(RE)과 접전 후반의 승리확률(WP) 변화를 따로 본다. 득점 기대값과 경기 승리 가능성은 같은 목적이 아니다.

## 현재 배포 코드의 수치와 동작

값의 실제 위치는 `dist/app.js`, `dist/enhancements.js`다.

### 공통 타석 분포 (모두 샘플값)

| 결과 | 현재 생성 규칙 |
|---|---|
| 타석 표본 | 결과 분포 100,000회 생성 후 빈도에 비례해 단 한 번 추첨. 최빈 결과를 강제로 선택하지 않는다. |
| 추정 타율 | 타자 샘플 AVG + 0.015 − (상대 선발 샘플 ERA − 0.25) × 0.22, 우선 0.15~0.38로 제한 |
| 볼넷 | 샘플 OBP × 0.30, 0.035~0.15로 제한 |
| 홈런 | 샘플 HR 값, 0.012~0.075로 제한 |
| 기본 삼진 | 타석 결과 확률 0.21 |
| 몸에 맞는 공 | 타석 결과 확률 0.012 |
| 인플레이 안타 분배 | 홈런 외 안타 확률 중 1루타 ×0.70, 2루타 ×0.27, 3루타 ×0.02 |
| 잔여 확률 | 아웃으로 배정 |
| 병살 | 1루 주자가 있고 0·1아웃이면 아웃 확률의 10%를 병살로 분리 |

이것은 실제 KBO 통계 모델이 아니다. 실제 기록으로 대체할 때는 AVG를 그대로 다음 타석 안타 확률로 쓰지 않고, 안타 종류·볼넷·삼진·사구·병살 등을 각각 추정해야 한다.

### 작전별 현재 샘플 계수

| 작전 | 코드상 변화 | 트레이드오프·상태 |
|---|---|---|
| 기본 타격 | 기본 타자·투수 샘플 분포 | 다른 작전 비교의 기준 |
| 컨택 타격 | 삼진 −5%p, 1루타 +2.5%p, 2루타·3루타·홈런 각각 ×0.80. 남은 질량은 아웃에 배정 | 맞히기와 단타 가능성을 높이는 대신 장타를 줄인다. 1루 주자와 0·1아웃이면 잔여 아웃 중 10%가 병살이라 병살 위험도 커질 수 있다. **임시 계수** |
| 강공 | 삼진 +4%p, 볼넷 ×0.70, 1루타 ×0.95, 2루타·3루타·홈런 각각 ×1.20. 남은 질량은 아웃에 배정 | 장타 가능성을 높이는 대신 삼진을 늘리고 볼넷·단타를 줄인다. **임시 계수** |
| 희생번트 | 1루 주자 및 0·1아웃에서만 현재 후보. 시도 100,000회 중 72%를 희생번트 성공(SAC), 28%를 타자 아웃(BUNT_FAIL)으로 추정 | 72/28은 참고 자료에서 가져온 값이 아니며 KBO 성공률도 아니다. 리드 주자 아웃, 번트 파울/삼진, 번트 안타, 수비 실책을 모델링하지 않는다. 정식 작전표에 그대로 가져가면 안 되는 **데모용 단순화** |
| 볼 참기 | 구현 안 됨 | 결과 확률에 고정 보너스를 주지 않는다. 투구별 볼/스트라이크 확률을 계산해야 볼넷 증가와 루킹 삼진 위험을 함께 표시할 수 있다. |
| 히트앤런·도루 | 구현 안 됨 | 주자 진루와 도루 실패/주루사, 타자 헛스윙, 병살 변화가 필요하다. 현재처럼 PA 결과만 사후 추첨하는 엔진으로는 정확하게 표시할 수 없다. |
| 희생플라이·스퀴즈 | 구현 안 됨 | 플라이 아웃 득점, 태그업, 번트 득점 시도, 홈에서의 주자 아웃/세이프 결과 유형이 먼저 필요하다. |

현재 컨택·강공 투표는 위의 상대 배율만 문장으로 적지 않는다. 다음 타자의 샘플 기본 분포와 작전 분포를 실제 엔진 함수로 각각 계산하고, 결과별 **절대 확률 차이(%p)** 를 비교해 화면에 노출한다. 단타·장타·볼넷·사구가 늘면 초록색, 줄면 빨간색이다. 삼진·일반 아웃·병살이 늘면 빨간색, 줄면 초록색이다. 따라서 나쁜 결과가 증가하거나 좋은 결과가 감소하는 경우도 빨간색으로 보인다. 이 색은 결과의 유불리 표기이지 KBO 실측을 뜻하지 않는다.

상황 문구는 `6회 초 · 무사 1,2루`, `7회 말 · 2아웃 만루`처럼 정리한다. 0아웃은 `무사`, 세 주자가 모두 있으면 `만루`, 둘 이상은 `1,3루`처럼 축약한다.

작전 투표는 투구 또는 매 볼카운트마다 띄우지 않는다. 직전 타석 종료 후 다음 조건에서만 다음 타석 작전 창을 연다: 2루 또는 3루 주자가 있어 득점권 작전이 가능한 경우, 1루 주자가 있고 0·1아웃이라 주루/번트 선택이 의미 있는 경우, 또는 7회 이후 점수 차가 2점 이내인 접전. 선택은 다음 타석에 한 번 적용된다. 이 기준은 샘플 MVP 임시 규칙이며, 모든 후보가 실제로 가능한 상황인지 24개 상태표와 대조해 후속 보정한다.

## 제안하는 24개 상황표

표의 선택지는 투표 후보의 설계안이며, 실제 확률·점수 차에 따라 추가 필터가 필요하다. ‘볼 참기’는 카운트 모델이 추가된 뒤에만 표시한다. 도루/히트앤런은 주자 속도와 투수·포수 데이터가 있을 때만 표시한다. 희생플라이/스퀴즈는 엔진 결과 유형 추가 전에는 표시하지 않는다.

| 주자 배치 | 0아웃 | 1아웃 | 2아웃 |
|---|---|---|---|
| 없음 | 기본, 컨택, 강공; 카운트가 유리하면 볼 참기 | 기본, 컨택, 강공; 카운트 조건부 볼 참기 | 기본, 컨택, 강공; 번트/희생플라이 제외 |
| 1루 | 기본, 히트앤런·도루(주자 조건), 번트(특수 조건) | 기본, 히트앤런·도루(주자 조건); 보통 희생번트 제외 | 기본, 강공/컨택; 번트 제외 |
| 2루 | 기본, 컨택, 강공; 3루 도루는 주자 조건부 | 기본, 컨택, 강공; 3루 도루는 주자 조건부 | 기본, 컨택/강공; 번트 제외 |
| 3루 | 기본, 희생플라이 유형, 스퀴즈(점수·타자·주자 조건) | 기본, 희생플라이 유형, 스퀴즈는 매우 제한적으로 | 기본, 컨택/강공; 희생플라이·스퀴즈 제외 |
| 1·2루 | 기본, 컨택, 볼 참기; 번트는 후반 1점 작전 등 제한 조건 | 기본, 컨택/강공, 히트앤런은 낮은 빈도 후보 | 기본, 컨택/강공; 번트 제외 |
| 1·3루 | 기본, 컨택, 히트앤런/스퀴즈는 조건부 | 기본, 컨택, 히트앤런/스퀴즈는 조건부 | 기본, 컨택/강공; 번트·스퀴즈 제외 |
| 2·3루 | 기본, 컨택/강공, 스퀴즈는 조건부 | 기본, 컨택/강공, 스퀴즈는 조건부 | 기본, 컨택/강공; 번트·스퀴즈 제외 |
| 만루 | 기본, 컨택, 볼 참기; 강공은 점수 상황에 따라 | 기본, 컨택, 볼 참기; 밀어내기 볼넷 가치 고려 | 기본, 강공/컨택; 번트 제외 |

### 점수·이닝·선수 조건

- **초반·큰 점수차:** 한 점만 노리는 번트/스퀴즈를 더 제한한다. 이닝 전체 득점 기대를 중시한다.
- **후반 1점 접전:** 한 점의 승리확률 가치가 커질 수 있다. 그래도 작전 성공/실패의 승리확률을 비교한 뒤 후보를 낸다.
- **타자:** 번트 능력, 삼진·볼넷·장타 분포, 타순상 후속 타자 능력을 반영한다.
- **주자:** 속도, 주루 판단, 현재 베이스, 다음 타자 결과 분포를 반영한다.
- **수비/배터리:** 투수 견제, 포수 송구, 내야 수비와 수비 위치를 도루·번트 결과에 반영한다.
- 24개 상태 각각에 독립된 숫자를 임의 지정하지 않는다. 희귀한 상황은 가까운 상태 및 리그 평균으로 축약 추정하고, 추정 표본 수와 신뢰 구간을 보존한다.

## 트레이드오프 모델 제안

| 작전 | 성공에서 얻는 것 | 치르는 위험 | 확률 산정에 필요한 기록 |
|---|---|---|---|
| 컨택 | 삼진 감소, 인플레이 타구 증가, 일부 상황에서 주자 진루 | 장타 감소, 약한 타구/병살 증가 가능 | 카운트별 삼진·인플레이·타구 유형·병살, 타자와 투수 좌우 |
| 강공 | 장타와 다득점 가능성 | 삼진 증가, 볼넷/단타 감소, 주자가 있을 때 병살 리스크 | 타구 속도/장타율 또는 종류별 안타, 삼진, 볼넷, 주자 상태 |
| 볼 참기 | 볼넷·투구 수 증가, 좋은 공을 기다림 | 루킹 스트라이크·삼진, 타격 가능한 공을 놓침 | 투구 단위 위치·콜, 카운트, 타자 존별 스윙, 투수 제구 |
| 희생번트 | 타자 아웃을 대가로 주자를 앞 베이스로 옮길 수 있음 | 번트 실패/선행주자 아웃, 이닝 아웃 소모, 장타 기회 상실 | 번트 시도/성공/파울/실패/번트 안타, 주자·수비 위치, 타자 번트 능력 |
| 히트앤런 | 땅볼 병살 회피, 타구 시 주자 추가 진루 | 헛스윙 시 도루자, 볼넷 기회 감소, 라인드라이브/타구에 따른 위험 | 주자 스타트·도루 성공/실패, 타석 결과, 타구 유형, 수비 위치 |
| 도루 | 아웃을 감수해 주자 득점 기대를 높임 | 도루 실패 시 아웃과 주자 제거 | 주자 속도/성공률, 투수 견제, 포수 송구, 카운트 |
| 희생플라이/스퀴즈 | 3루 주자 득점 | 타자 아웃, 태그업/홈 접전사, 번트 파울·삼진 | 외야 플라이 거리·수비, 주자 속도, 홈 송구, 번트 결과 |

작전 확률은 ‘좋아 보이는 결과만 증가’시키는 값이 아니라, 같은 상황에서 대안별 결과 분포를 만들어야 한다. 예: 히트앤런이면 `안타 + 추가 진루`, `땅볼 + 병살 회피`, `헛스윙 + 도루 성공/실패`, `볼/볼넷 기회 손실` 모두 한 분포 안에 들어간다.

## 근거 자료와 사용 내용

아래 자료는 작전 구조와 비교 방법을 설계할 때 참고했다. MLB/NPB 결과를 KBO 수치라고 옮기지 않는다.

1. **Baseball Savant, Game Strategy Explorer** — https://baseballsavant.mlb.com/game-strategy-explorer (접속: 2026-11-05)
   - 2016~2025 MLB 상황을 기준으로 이닝·초/말·점수·아웃·주자·카운트에 따른 기대득점과 승리확률을 비교한다.
   - 사용 내용: 작전 전후의 상태를 비교하고, RE와 WP를 구분하는 설계 원칙. 이 도구의 수치는 KBO 데이터가 아니다.
2. **MLB.com, “Baseball Savant releases Game Strategy Explorer”** — https://www.mlb.com/news/baseball-savant-releases-game-strategy-explorer (접속: 2026-11-05)
   - 동점 9회초 무사 1루 예시에서 희생번트 성공은 타격팀 승리확률 −4.9%p, 선행주자 아웃은 −29.2%p로 보고한다.
   - 사용 내용: 번트 성공률만 보여주지 말고, 성공해도 이닝/점수 상황에 따라 기대 승리확률이 떨어질 수 있음을 표시한다.
3. **Hiroshima et al., “The effect of sacrifice bunt in baseball, executed when a runner is on first base with no outs,” Japan Journal of Coaching Studies 24(2), 2011** — https://www.jstage.jst.go.jp/article/jcoaching/24/2/24_119/_article (접속: 2026-11-05)
   - 2006년 일본 프로야구 846경기 중 상황 자료를 분석. 무사 1루 사례에서 이닝 기대득점이 번트 0.73, 강공 0.86, 히트앤런 0.95였다고 보고한다.
   - 사용 내용: 일반적인 무사 1루 번트를 기본 추천으로 만들지 않는 근거. 단일 연도·일본 리그 결과여서 KBO 계수로 사용하지 않는다.
4. **Pete Palmer/SABR, “Does the hit-and-run help?”** — https://sabr.org/latest/palmer-does-the-hit-and-run-help/ (접속: 2026-11-05)
   - 2004~2011 MLB 자료 분석. 히트앤런은 추가 진루와 병살 회피에 도움이 된 면이 있었으나 홈런·볼넷 감소, 라인드라이브 병살과 헛스윙 시 주루 위험도 언급한다.
   - 사용 내용: 히트앤런은 안타 확률만 높이는 버튼이 아니라 타자·주자 결과를 함께 모델링해야 한다.
5. **Jim Albert, “Beyond runs expectancy,” Journal of Quantitative Analysis in Sports, 2015** — https://journals.sagepub.com/doi/10.3233/JSA-140001
   - 아웃 3가지와 주자 8가지가 24 base/out state를 만들며, 상황별 잔여 득점 분포로 작전을 평가하는 전통을 설명한다.
   - 사용 내용: 작전 후보를 24개 base/out 상태에서 시작하는 이유.
6. **FanGraphs Sabermetrics Library, Run Expectancy Matrix** — https://library.fangraphs.com/misc/re24/ (접속: 2026-11-05)
   - 2010~2015 MLB run expectancy 예시와 상태별 차이를 소개한다.
   - 사용 내용: 점수 기대의 상태 의존성을 설명하는 보조 참고. KBO 임시 수치로 복사하지 않는다.

## KBO 보정 작업 순서

1. 합법적인 공급원에서 투구/타석 이벤트를 받을 수 있는지와 사용 권한을 확인한다.
2. 경기 날짜 기준으로 미래 기록을 배제하고, 각 이벤트를 결과·주자 이동·아웃·득점으로 정규화한다.
3. 24개 base/out state와 점수/이닝/카운트, 타자·투수 좌우, 주자 속도, 수비를 키로 결과 분포를 산출한다.
4. 선수 표본이 적으면 이전 시즌과 리그 평균으로 shrinkage하고, 사용 표본과 구간을 함께 저장한다.
5. 작전별 성공/실패/부수 결과 분포를 적용해 작전 전후 RE와 후반 접전 WP를 계산한다.
6. 개발 검증은 반복 시뮬레이션으로 하되, 공식 경기는 시드와 입력 스냅샷을 고정해 한 번만 실행한다.
7. 각 경기의 능력치 스냅샷·기준 날짜·엔진 버전·선택 작전·확률 계수·난수 시드를 저장해 과거 결과를 재현한다.

## 테스트 초기화 메모

- 관리자 URL `?admin=1`에서 **테스트 초기화**는 이 브라우저의 샘플 경기, 제출 라인업, 즐겨찾기와 투표 상태를 모두 초기화한다.
- **현재 경기 초기화 후 다시 실행**은 경기 상태만 지우며 라인업과 응원팀 설정은 보존한다.
- 테스트 초기화 후에는 관리자 경기 센터에서 **관리자 경기 즉시 시작**을 누른다. 기본 샘플 라인업은 `ln()`에서 자동 생성된다.
- 상태는 현재 브라우저의 localStorage에 저장되며, 서버 DB/다른 사용자 간 동기화는 아직 없다.
